# Подробные ответы по темам: 3DES, Режимы шифрования, Rabbit, MAC

---

## 1. 3DES (Triple DES) — Тройной DES

### 1.1 Предпосылки создания

Алгоритм DES (Data Encryption Standard) был принят в 1977 году с длиной ключа 56 бит. К 1990-м годам стало очевидно, что 56-битный ключ уязвим к атаке полного перебора (brute force). В 1998 году машина Deep Crack взломала DES за 56 часов.

Решением стало **многократное применение DES** — так появился 3DES (Triple DES, TDEA — Triple Data Encryption Algorithm).

---

### 1.2 Структура 3DES

**Базовые параметры:**
- Размер блока: **64 бита** (как у DES)
- Длина ключа: **112 или 168 бит** (в зависимости от варианта)
- Количество раундов: **48 раундов** (3 × 16 раундов DES)

**Схема работы:**

```
┌────────────────────────────────────────────────────────┐
│                    3DES-EDE                            │
│                                                        │
│  Открытый текст (64 бита)                             │
│         │                                              │
│         ▼                                              │
│  ┌─────────────┐                                       │
│  │ DES-Encrypt │ ← Ключ K₁ (56 бит)                   │
│  └─────────────┘                                       │
│         │                                              │
│         ▼                                              │
│  ┌─────────────┐                                       │
│  │ DES-Decrypt │ ← Ключ K₂ (56 бит)                   │
│  └─────────────┘                                       │
│         │                                              │
│         ▼                                              │
│  ┌─────────────┐                                       │
│  │ DES-Encrypt │ ← Ключ K₃ (56 бит)                   │
│  └─────────────┘                                       │
│         │                                              │
│         ▼                                              │
│  Шифротекст (64 бита)                                 │
└────────────────────────────────────────────────────────┘
```

---

### 1.3 Варианты 3DES

#### Вариант 1: Три независимых ключа (Keying Option 1)
- **Ключи:** K₁, K₂, K₃ — все разные
- **Общая длина:** 168 бит (3 × 56)
- **Эффективная стойкость:** ~112 бит (из-за атаки meet-in-the-middle)

#### Вариант 2: Два независимых ключа (Keying Option 2)
- **Ключи:** K₁ ≠ K₂, но K₃ = K₁
- **Общая длина:** 112 бит (2 × 56)
- **Эффективная стойкость:** ~80-112 бит
- **Наиболее распространённый вариант**

#### Вариант 3: Один ключ (Keying Option 3)
- **Ключи:** K₁ = K₂ = K₃
- **Эквивалентен обычному DES**
- **Используется для обратной совместимости**

---

### 1.4 Процедура шифрования 3DES-EDE

**EDE** означает **Encrypt-Decrypt-Encrypt** (Зашифровать-Расшифровать-Зашифровать).

**Математическая формула:**
```
C = E_K₁(D_K₂(E_K₃(P)))
```

Где:
- P — открытый текст (plaintext)
- C — шифротекст (ciphertext)
- E_Kᵢ — шифрование DES с ключом Kᵢ
- D_Kᵢ — дешифрование DES с ключом Kᵢ

**Пошаговый алгоритм шифрования:**

```
Шаг 1: Первое шифрование
       Temp₁ = DES-Encrypt(P, K₃)
       
       Внутри DES:
       1.1. Начальная перестановка IP(P)
       1.2. Разделение на L₀ и R₀ (по 32 бита)
       1.3. 16 раундов сети Фейстеля:
            Lᵢ = Rᵢ₋₁
            Rᵢ = Lᵢ₋₁ ⊕ F(Rᵢ₋₁, Kᵢ)
       1.4. Финальная перестановка IP⁻¹

Шаг 2: Промежуточное дешифрование
       Temp₂ = DES-Decrypt(Temp₁, K₂)
       
       (Те же операции, но раундовые ключи 
        применяются в обратном порядке: K₁₆, K₁₅, ..., K₁)

Шаг 3: Финальное шифрование
       C = DES-Encrypt(Temp₂, K₁)
```

**Почему EDE, а не EEE?**
- При K₁ = K₂ = K₃: EDE эквивалентен одинарному DES
- Обеспечивает **обратную совместимость** с существующими системами DES
- EEE не даёт такой совместимости

---

### 1.5 Процедура дешифрования 3DES

**Математическая формула:**
```
P = D_K₃(E_K₂(D_K₁(C)))
```

**Пошаговый алгоритм дешифрования:**

```
Шаг 1: Первое дешифрование
       Temp₁ = DES-Decrypt(C, K₁)
       
       Внутри DES-Decrypt:
       1.1. Начальная перестановка IP(C)
       1.2. Разделение на L₀ и R₀
       1.3. 16 раундов с ключами в обратном порядке
       1.4. Финальная перестановка IP⁻¹

Шаг 2: Промежуточное шифрование
       Temp₂ = DES-Encrypt(Temp₁, K₂)

Шаг 3: Финальное дешифрование
       P = DES-Decrypt(Temp₂, K₃)
```

**Симметрия EDE:**
- Шифрование: E(K₁) → D(K₂) → E(K₃)
- Дешифрование: D(K₁) → E(K₂) → D(K₃)

---

### 1.6 Расширение ключа в 3DES

Для каждого из трёх DES-преобразований генерируются свои 16 раундовых ключей:

```
Для ключа K₁: K₁,₁, K₁,₂, ..., K₁,₁₆ (48 бит каждый)
Для ключа K₂: K₂,₁, K₂,₂, ..., K₂,₁₆ (48 бит каждый)
Для ключа K₃: K₃,₁, K₃,₂, ..., K₃,₁₆ (48 бит каждый)

Итого: 48 раундовых ключей
```

**Алгоритм расширения ключа DES:**

```
1. PC-1 (Permuted Choice 1):
   - Вход: 64 бита (с битами чётности)
   - Выход: 56 бит (удаляются биты 8, 16, 24, 32, 40, 48, 56, 64)

2. Разделение на C₀ и D₀ (по 28 бит)

3. Для каждого раунда i = 1..16:
   - Циклический сдвиг влево:
     Cᵢ = LS(Cᵢ₋₁)
     Dᵢ = LS(Dᵢ₋₁)
   
   - Величина сдвига:
     Раунды 1, 2, 9, 16: сдвиг на 1 бит
     Остальные раунды: сдвиг на 2 бита

4. PC-2 (Permuted Choice 2):
   - Вход: Cᵢ || Dᵢ (56 бит)
   - Выход: Kᵢ (48 бит)
```

---

### 1.7 Безопасность 3DES

**Атака "Встреча посередине" (Meet-in-the-Middle):**

Для двойного DES (2DES) с двумя ключами K₁ и K₂:
- Шифрование: C = E_K₂(E_K₁(P))
- Атака: вычислить E_K₁(P) для всех K₁ и D_K₂(C) для всех K₂
- Сравнить результаты → найти совпадение
- Сложность: 2⁵⁷ вместо ожидаемых 2¹¹²

**Для 3DES:**
- Атака meet-in-the-middle сложнее
- Сложность: ~2¹¹² операций
- Требуется значительный объём памяти

**Известные атаки:**
- Sweet32 (2016): атака на блоки 64 бита при большом объёме данных
- Рекомендация: ограничивать объём данных на одном ключе

---

### 1.8 Применение и статус 3DES

**Историческое применение:**
- Банковские системы (EMV, ATM)
- Протоколы SSL/TLS (до 2015)
- VPN, IPsec

**Современный статус:**
- NIST deprecated 3DES в 2017 году
- Запрещён после 2023 года для новых систем
- Рекомендуется замена на AES

## 2. Режимы шифрования блочных шифров

### 2.1 ECB (Electronic Codebook Mode)

**Принцип работы:**
Каждый блок шифруется независимо с одним и тем же ключом.

```
Шифрование:
┌────┐    ┌────┐    ┌────┐
│ P₁ │    │ P₂ │    │ P₃ │
└──┬─┘    └──┬─┘    └──┬─┘
   │         │         │
   ▼         ▼         ▼
┌──────┐  ┌──────┐  ┌──────┐
│E(K)  │  │E(K)  │  │E(K)  │
└──┬───┘  └──┬───┘  └──┬───┘
   │         │         │
   ▼         ▼         ▼
┌────┐    ┌────┐    ┌────┐
│ C₁ │    │ C₂ │    │ C₃ │
└────┘    └────┘    └────┘

Формулы:
Шифрование: Cᵢ = E_K(Pᵢ)
Дешифрование: Pᵢ = D_K(Cᵢ)
```

**Характеристики:**
| Свойство | Значение |
|----------|----------|
| IV | Не требуется |
| Параллелизм шифрования | Да |
| Параллелизм дешифрования | Да |
| Распространение ошибок | Только в пределах блока |
| Padding | Требуется |

**Критическая уязвимость:**
- Одинаковые блоки открытого текста → одинаковые блоки шифротекста
- Утечка структуры данных (пример: шифрование изображения)
- **НЕ РЕКОМЕНДУЕТСЯ К ИСПОЛЬЗОВАНИЮ**

---

### 2.2 CBC (Cipher Block Chaining)

**Принцип работы:**
Каждый блок XOR-ится с предыдущим шифротекстом перед шифрованием.

```
Шифрование:
        IV           C₁           C₂
         │            │            │
         ▼            ▼            ▼
┌────┐ ┌───┐  ┌────┐ ┌───┐  ┌────┐ ┌───┐
│ P₁ │→│XOR│  │ P₂ │→│XOR│  │ P₃ │→│XOR│
└────┘ └─┬─┘  └────┘ └─┬─┘  └────┘ └─┬─┘
         │             │             │
         ▼             ▼             ▼
      ┌──────┐      ┌──────┐      ┌──────┐
      │ E(K) │      │ E(K) │      │ E(K) │
      └──┬───┘      └──┬───┘      └──┬───┘
         │             │             │
         ▼             ▼             ▼
       ┌────┐        ┌────┐        ┌────┐
       │ C₁ │───────►│ C₂ │───────►│ C₃ │
       └────┘        └────┘        └────┘

Формулы:
Шифрование: C₀ = IV
            Cᵢ = E_K(Pᵢ ⊕ Cᵢ₋₁)

Дешифрование: Pᵢ = D_K(Cᵢ) ⊕ Cᵢ₋₁
              P₁ = D_K(C₁) ⊕ IV
```

**Характеристики:**
| Свойство | Значение |
|----------|----------|
| IV | Требуется (случайный, уникальный) |
| Параллелизм шифрования | Нет |
| Параллелизм дешифрования | Да |
| Распространение ошибок | 2 блока |
| Padding | Требуется |

**Особенности:**
- IV должен быть непредсказуемым (случайным)
- Одинаковые сообщения с разными IV → разные шифротексты
- Уязвим к padding oracle attack (без MAC)

---

### 2.3 CFB (Cipher Feedback Mode)

**Принцип работы:**
Блочный шифр используется как генератор ключевого потока.

```
Шифрование:
    IV         C₁         C₂
     │          │          │
     ▼          ▼          ▼
  ┌──────┐   ┌──────┐   ┌──────┐
  │ E(K) │   │ E(K) │   │ E(K) │
  └──┬───┘   └──┬───┘   └──┬───┘
     │          │          │
     ▼          ▼          ▼
   ┌───┐      ┌───┐      ┌───┐
P₁→│XOR│   P₂→│XOR│   P₃→│XOR│
   └─┬─┘      └─┬─┘      └─┬─┘
     │          │          │
     ▼          ▼          ▼
    C₁─────────►C₂─────────►C₃

Формулы (для полноблочного CFB):
Шифрование: I₁ = IV
            Iᵢ = Cᵢ₋₁ для i > 1
            Cᵢ = Pᵢ ⊕ E_K(Iᵢ)

Дешифрование: Pᵢ = Cᵢ ⊕ E_K(Iᵢ)
```

**CFB-s (s-битный CFB):**
- Позволяет работать с блоками меньше размера блока шифра
- Например, CFB-8 обрабатывает по 1 байту
- Менее эффективен, но гибче

**Характеристики:**
| Свойство | Значение |
|----------|----------|
| IV | Требуется |
| Параллелизм шифрования | Нет |
| Параллелизм дешифрования | Да |
| Распространение ошибок | 1 бит ошибки → ~1.5 блока повреждено |
| Padding | Не требуется (для CFB-8) |

---

### 2.4 OFB (Output Feedback Mode)

**Принцип работы:**
Генерирует ключевой поток независимо от открытого текста и шифротекста.

```
Шифрование:
    IV          O₁         O₂
     │           │          │
     ▼           ▼          ▼
  ┌──────┐   ┌──────┐   ┌──────┐
  │ E(K) │   │ E(K) │   │ E(K) │
  └──┬───┘   └──┬───┘   └──┬───┘
     │           │          │
     ▼           ▼          ▼
    O₁──────────►O₂─────────►O₃
     │           │          │
     ▼           ▼          ▼
   ┌───┐       ┌───┐      ┌───┐
P₁→│XOR│    P₂→│XOR│   P₃→│XOR│
   └─┬─┘       └─┬─┘      └─┬─┘
     │           │          │
     ▼           ▼          ▼
    C₁          C₂         C₃

Формулы:
Генерация потока: O₀ = IV
                  Oᵢ = E_K(Oᵢ₋₁)

Шифрование: Cᵢ = Pᵢ ⊕ Oᵢ
Дешифрование: Pᵢ = Cᵢ ⊕ Oᵢ
```

**Характеристики:**
| Свойство | Значение |
|----------|----------|
| IV | Требуется (уникальный, nonce) |
| Параллелизм шифрования | Нет (но поток можно предвычислить) |
| Параллелизм дешифрования | Нет (но поток можно предвычислить) |
| Распространение ошибок | Нет (1 бит ошибки → 1 бит) |
| Padding | Не требуется |

**Особенности:**
- Синхронный потоковый режим
- Ключевой поток можно предвычислить заранее
- Критично: НЕЛЬЗЯ использовать один IV дважды!

---

### 2.5 CTR (Counter Mode)

**Принцип работы:**
Шифрует последовательные значения счётчика для генерации ключевого потока.

```
Шифрование:
  Nonce||1    Nonce||2    Nonce||3
     │           │           │
     ▼           ▼           ▼
  ┌──────┐   ┌──────┐    ┌──────┐
  │ E(K) │   │ E(K) │    │ E(K) │
  └──┬───┘   └──┬───┘    └──┬───┘
     │           │           │
     ▼           ▼           ▼
   ┌───┐       ┌───┐       ┌───┐
P₁→│XOR│    P₂→│XOR│    P₃→│XOR│
   └─┬─┘       └─┬─┘       └─┬─┘
     │           │           │
     ▼           ▼           ▼
    C₁          C₂          C₃

Формулы:
Шифрование: Cᵢ = Pᵢ ⊕ E_K(Nonce || Counter_i)
Дешифрование: Pᵢ = Cᵢ ⊕ E_K(Nonce || Counter_i)
```

**Структура счётчика (для AES-128):**
```
|←────── 128 бит ──────→|
|   Nonce (64 бит)   | Counter (64 бит) |
```

**Характеристики:**
| Свойство | Значение |
|----------|----------|
| IV/Nonce | Требуется (уникальный) |
| Параллелизм шифрования | Да (полный) |
| Параллелизм дешифрования | Да (полный) |
| Распространение ошибок | Нет |
| Padding | Не требуется |
| Произвольный доступ | Да |

**Преимущества CTR:**
- Полный параллелизм → высокая производительность
- Произвольный доступ к любому блоку
- Нет padding → точный размер шифротекста
- Простая реализация

**Применение:**
- IPsec (ESP)
- TLS 1.3
- Disk encryption (с XTS)

---

### 2.6 GCM (Galois/Counter Mode)

**Принцип работы:**
Комбинация CTR для шифрования и GHASH для аутентификации.

```
Структура GCM:
                                      
         J₀           J₁           J₂
          │            │            │
          ▼            ▼            ▼
       ┌──────┐     ┌──────┐     ┌──────┐
       │ E(K) │     │ E(K) │     │ E(K) │
       └──┬───┘     └──┬───┘     └──┬───┘
          │            │            │
          ▼            ▼            ▼
         H         ┌───┐         ┌───┐
          │     P₁→│XOR│      P₂→│XOR│
          │        └─┬─┘         └─┬─┘
          │           │            │
          │           ▼            ▼
          │          C₁           C₂
          │           │            │
          ▼           ▼            ▼
       ┌─────────────────────────────┐
       │         GHASH(H)            │
       │  (полиномиальное умножение  │
       │   в поле Галуа GF(2¹²⁸))    │
       └─────────────┬───────────────┘
                     │
                     ▼
                   Tag (128 бит)

Где: J₀ = IV || 0³¹ || 1  (если len(IV) = 96 бит)
     Jᵢ = incr(Jᵢ₋₁)
     H = E_K(0¹²⁸)  — ключ аутентификации
```

**GHASH функция:**
```
GHASH(H, A, C) = X_m+n+1

Где:
- A = дополнительные аутентифицируемые данные (AAD)
- C = шифротекст
- H = E_K(0¹²⁸)

Вычисление:
X₀ = 0
Xᵢ = (Xᵢ₋₁ ⊕ Aᵢ) • H     для i = 1..m (AAD)
Xᵢ = (Xᵢ₋₁ ⊕ Cᵢ₋ₘ) • H   для i = m+1..m+n (шифротекст)
X_{m+n+1} = (X_{m+n} ⊕ (len(A) || len(C))) • H
```

**Формат GCM:**
```
Вход: (K, IV, P, A)
  K — ключ
  IV — вектор инициализации (рекомендуется 96 бит)
  P — открытый текст
  A — дополнительные аутентифицируемые данные (AAD)

Выход: (C, Tag)
  C — шифротекст
  Tag — тег аутентификации (128 бит)
```

**Характеристики:**
| Свойство | Значение |
|----------|----------|
| IV/Nonce | Требуется (12 байт рекомендуется) |
| Параллелизм | Да (полный) |
| Аутентификация | Да (встроенная) |
| AAD | Поддерживается |
| Размер тега | 128, 120, 112, 104, 96 бит |

**AEAD (Authenticated Encryption with Associated Data):**
- Обеспечивает конфиденциальность И целостность
- AAD аутентифицируется, но не шифруется
- Пример AAD: заголовки пакетов, метаданные

**Применение:**
- TLS 1.2, 1.3 (AES-GCM)
- IPsec
- SSH
- Дисковое шифрование

---

### 2.7 Сравнительная таблица режимов

| Режим | IV | Параллелизм | Padding | MAC | Безопасность | Рекомендация |
|-------|-----|-------------|---------|-----|--------------|--------------|
| ECB | Нет | Да/Да | Да | Нет | ⚠️ Низкая | НЕ использовать |
| CBC | Да | Нет/Да | Да | Нет | ✓ Средняя | + MAC |
| CFB | Да | Нет/Да | Нет | Нет | ✓ Средняя | Редко |

| GCM | Да | Да/Да | Нет | Да | ✓✓ Высокая | **Рекомендуется** |

## 3. Потоковый шифр Rabbit

### 3.1 Общая информация

**Rabbit** — высокоскоростной потоковый шифр, разработанный в 2003 году компанией Cryptico A/S (Дания). Финалист проекта eSTREAM (профиль 1 — программные реализации).

**Основные параметры:**
- Длина ключа: **128 бит**
- Длина IV: **64 бита** (опционально)
- Размер состояния: **513 бит**
- Выход за итерацию: **128 бит**

---

### 3.2 Структура Rabbit

**Внутреннее состояние:**

```
┌────────────────────────────────────────────────────┐
│              Состояние Rabbit (513 бит)            │
├────────────────────────────────────────────────────┤
│  X₀, X₁, X₂, X₃, X₄, X₅, X₆, X₇  — 8×32 = 256 бит │
│  (основные регистры состояния)                     │
├────────────────────────────────────────────────────┤
│  C₀, C₁, C₂, C₃, C₄, C₅, C₆, C₇  — 8×32 = 256 бит │
│  (счётчики)                                        │
├────────────────────────────────────────────────────┤
│  φ — бит переноса (carry bit) — 1 бит             │
└────────────────────────────────────────────────────┘
```

---

### 3.3 Инициализация ключа

**Входные данные:** 128-битный ключ K = k₀||k₁||...||k₁₅ (16 байт)

**Алгоритм:**

```
1. Разделить ключ на 8 подключей по 16 бит:
   K[j] = k₂ⱼ || k₂ⱼ₊₁  для j = 0..7

2. Инициализировать регистры состояния:
   Для чётных j (j = 0, 2, 4, 6):
       X[j] = K[(j+1) mod 8] || K[j]
   Для нечётных j (j = 1, 3, 5, 7):
       X[j] = K[(j+5) mod 8] || K[(j+4) mod 8]

3. Инициализировать счётчики:
   Для чётных j:
       C[j] = K[(j+4) mod 8] || K[(j+5) mod 8]
   Для нечётных j:
       C[j] = K[j] || K[(j+1) mod 8]

4. Установить бит переноса:
   φ = 0

5. Выполнить 4 итерации системы (без вывода):
   Для i = 0..3:
       next_state()
   
6. Реинициализировать счётчики:
   Для j = 0..7:
       C[j] = C[j] ⊕ X[(j+4) mod 8]
```

---

### 3.4 Инициализация IV (опционально)

**Если используется 64-битный IV:**

```
1. Разделить IV на 4 части по 16 бит:
   IV = i₀||i₁||i₂||i₃

2. Модифицировать счётчики:
   C[0] = C[0] ⊕ (i₁ || i₀)
   C[1] = C[1] ⊕ (i₃ || i₁)
   C[2] = C[2] ⊕ (i₃ || i₂)
   C[3] = C[3] ⊕ (i₂ || i₀)
   C[4] = C[4] ⊕ (i₁ || i₀)
   C[5] = C[5] ⊕ (i₃ || i₁)
   C[6] = C[6] ⊕ (i₃ || i₂)
   C[7] = C[7] ⊕ (i₂ || i₀)

3. Выполнить ещё 4 итерации системы (без вывода)
```

---

### 3.5 Функция обновления состояния (next_state)

**Шаг 1: Обновление счётчиков**

```
Константы A[j]:
A[0] = 0x4D34D34D    A[1] = 0xD34D34D3
A[2] = 0x34D34D34    A[3] = 0x4D34D34D
A[4] = 0xD34D34D3    A[5] = 0x34D34D34
A[6] = 0x4D34D34D    A[7] = 0xD34D34D3

Для j = 0..7:
   temp = C[j] + A[j] + φ
   φ = temp >> 32  (новый бит переноса)
   C[j] = temp mod 2³²
```

**Шаг 2: Вычисление промежуточных значений G[j]**

```
Для j = 0..7:
   g[j] = (X[j] + C[j])² ⊕ ((X[j] + C[j])² >> 32)
   
   Более детально:
   temp = (X[j] + C[j]) mod 2³²
   temp² = temp × temp  (64-битное произведение)
   G[j] = (temp² mod 2³²) ⊕ (temp² >> 32)
```

**Шаг 3: Обновление регистров состояния**

```
X[0] = G[0] + (G[7] <<< 16) + (G[6] <<< 16)
X[1] = G[1] + (G[0] <<< 8)  + G[7]
X[2] = G[2] + (G[1] <<< 16) + (G[0] <<< 16)
X[3] = G[3] + (G[2] <<< 8)  + G[1]
X[4] = G[4] + (G[3] <<< 16) + (G[2] <<< 16)
X[5] = G[5] + (G[4] <<< 8)  + G[3]
X[6] = G[6] + (G[5] <<< 16) + (G[4] <<< 16)
X[7] = G[7] + (G[6] <<< 8)  + G[5]

Где <<< означает циклический сдвиг влево
Все операции + выполняются по модулю 2³²
```

---

### 3.6 Извлечение ключевого потока

**После каждого вызова next_state() извлекается 128 бит:**

```
S[0..15] = X[0] ⊕ X[5]>>16 ||    // биты 0-15
           X[0]>>16 ⊕ X[3] ||    // биты 16-31
           X[2] ⊕ X[7]>>16 ||    // биты 32-47
           X[2]>>16 ⊕ X[5] ||    // биты 48-63
           X[4] ⊕ X[1]>>16 ||    // биты 64-79
           X[4]>>16 ⊕ X[7] ||    // биты 80-95
           X[6] ⊕ X[3]>>16 ||    // биты 96-111
           X[6]>>16 ⊕ X[1]       // биты 112-127

Где >> означает логический сдвиг вправо
```

---

### 3.7 Процесс шифрования/дешифрования

```
Шифрование:
1. Инициализировать состояние ключом K (и IV, если используется)
2. Для каждых 128 бит открытого текста:
   a. next_state()
   b. Извлечь S (128 бит ключевого потока)
   c. C = P ⊕ S

Дешифрование:
   Идентичен шифрованию (XOR — обратимая операция)
```

---

### 3.8 Особенности и безопасность Rabbit

**Криптографические свойства:**
- Период: не менее 2¹⁵⁸
- Устойчивость к известным атакам
- Высокая скорость: ~3.7 циклов/байт (на x86)

**Применение:**
- eSTREAM portfolio (профиль 1)
- RFC 4503 (Rabbit in TLS)
- Лицензия: бесплатен для некоммерческого использования

**Преимущества:**
- Очень высокая производительность
- Простая структура для анализа
- Компактное состояние

**Ограничения:**
- Максимум 2⁶⁴ блоков с одним ключом/IV
- 64-битный IV (меньше, чем у современных шифров)

## 4. Код аутентификации сообщения (MAC)

### 4.1 Определение и назначение

**MAC (Message Authentication Code)** — криптографический примитив, обеспечивающий:

1. **Целостность данных** — обнаружение несанкционированных изменений
2. **Аутентификацию источника** — подтверждение, что сообщение от ожидаемого отправителя

**Отличие от хеш-функции:**
- Хеш: H(M) — любой может вычислить
- MAC: MAC(K, M) — только обладатель ключа K

**Отличие от цифровой подписи:**
- MAC: симметричный (один ключ для создания и проверки)
- Подпись: асимметричная (разные ключи)

---

### 4.2 Общая схема использования MAC

```
Отправитель (Алиса):                 Получатель (Боб):
                                    
1. Вычислить:                       4. Получить (M, T)
   T = MAC(K, M)                    
                                    5. Вычислить:
2. Отправить: (M, T)     ────►         T' = MAC(K, M)
                                    
                                    6. Проверить:
                                       T' == T ?
                                       - Да: сообщение подлинное
                                       - Нет: сообщение изменено/подделано
```

---

### 4.3 Типы MAC

#### 4.3.1 HMAC (Hash-based MAC)

**Структура HMAC:**

```
HMAC(K, M) = H((K' ⊕ opad) || H((K' ⊕ ipad) || M))

Где:
- H — криптографическая хеш-функция (SHA-256, SHA-512, и т.д.)
- K' — ключ, дополненный нулями до размера блока H
- ipad = 0x36 повторённый B раз (B — размер блока)
- opad = 0x5C повторённый B раз
```

**Пошаговый алгоритм HMAC:**

```
1. Подготовка ключа:
   Если len(K) > B: K' = H(K)
   Иначе: K' = K || 0...0 (дополнение до B байт)

2. Вычисление внутреннего хеша:
   inner = H((K' ⊕ ipad) || M)

3. Вычисление внешнего хеша:
   HMAC = H((K' ⊕ opad) || inner)
```

**Визуализация:**

```
         K' ⊕ ipad              K' ⊕ opad
             │                      │
             ▼                      ▼
        ┌─────────┐            ┌─────────┐
M ──────│   H()   │────────────│   H()   │───► HMAC
        └─────────┘            └─────────┘
            inner                 outer
```

**Примеры:**
- HMAC-SHA256: 256-битный выход
- HMAC-SHA512: 512-битный выход
- HMAC-MD5: 128 бит (устарел)

---

#### 4.3.2 CBC-MAC

**Принцип:** Используется блочный шифр в режиме CBC, тег = последний блок.

```
        ┌────┐   ┌────┐   ┌────┐   ┌────┐
   0 ──►│XOR│   │XOR│   │XOR│   │XOR│
        └─┬─┘   └─┬─┘   └─┬─┘   └─┬─┘
          │ M₁    │ M₂    │ M₃    │ M₄
          │  │    │  │    │  │    │  │
          │  ▼    │  ▼    │  ▼    │  ▼
          │┌───┐  │┌───┐  │┌───┐  │┌───┐
          ││XOR│  ││XOR│  ││XOR│  ││XOR│
          │└─┬─┘  │└─┬─┘  │└─┬─┘  │└─┬─┘
          │  │    │  │    │  │    │  │
          ▼  ▼    ▼  ▼    ▼  ▼    ▼  ▼
        ┌──────┐┌──────┐┌──────┐┌──────┐
        │ E(K) ││ E(K) ││ E(K) ││ E(K) │
        └──┬───┘└──┬───┘└──┬───┘└──┬───┘
           │       │       │       │
           └───────┴───────┴───────┴──► TAG

Формула:
C₀ = 0
Cᵢ = E_K(Cᵢ₋₁ ⊕ Mᵢ)
TAG = Cₙ
```

**Ограничения CBC-MAC:**
- Безопасен только для сообщений фиксированной длины
- Уязвим к атаке удлинения для переменной длины

---

#### 4.3.3 CMAC (Cipher-based MAC)

**Улучшенная версия CBC-MAC**, безопасная для сообщений переменной длины.

```
Генерация подключей:
L = E_K(0)
K₁ = L << 1  (если MSB(L) = 0)
   = (L << 1) ⊕ Rb  (если MSB(L) = 1)
K₂ = K₁ << 1 (аналогично)

Где Rb — константа для поля Галуа

Вычисление CMAC:
1. Если len(M) кратна блоку:
   Mₙ' = Mₙ ⊕ K₁
2. Иначе (с padding):
   Mₙ' = (Mₙ || 10...0) ⊕ K₂

3. TAG = CBC-MAC с модифицированным последним блоком
```

---

#### 4.3.4 GMAC (Galois MAC)

**GMAC** — это GCM без шифрования (только аутентификация).

```
GMAC(K, IV, A) = GHASH(H, A, "") ⊕ E_K(J₀)

Где:
- H = E_K(0)
- J₀ = IV || 0³¹ || 1
- A — аутентифицируемые данные
```

---

#### 4.3.5 Poly1305

**Современный быстрый MAC**, часто используется с ChaCha20.

```
Poly1305(K, M) = ((∑ mᵢ × r^(n-i)) mod (2¹³⁰ - 5)) + s

Где:
- K = (r, s) — 256-битный ключ
- r — "clamped" (некоторые биты обнулены)
- mᵢ — блоки сообщения (128 бит + 1 бит)
- Вычисления в поле GF(2¹³⁰ - 5)
```

---

### 4.4 Свойства безопасности MAC

**1. Стойкость к подделке (Unforgeability):**
- Атакующий не может создать валидный MAC без знания ключа
- Даже видя множество пар (M, MAC(K,M))

**2. Стойкость к восстановлению ключа:**
- Невозможно вычислить K из пар (M, MAC(K,M))

**3. Стойкость к коллизиям:**
- Сложно найти M₁ ≠ M₂ с одинаковым MAC

---

### 4.5 Атаки на MAC

**1. Атака повторного воспроизведения (Replay Attack):**
- Противник перехватывает (M, T) и повторно отправляет
- Защита: nonce, timestamp, sequence numbers

**2. Атака удлинения (Length Extension):**
- Для некоторых конструкций можно вычислить MAC(K, M||M') 
  зная только MAC(K, M)
- Уязвимы: H(K||M), CBC-MAC для переменной длины
- Защита: HMAC, CMAC

**3. Атака по времени (Timing Attack):**
- Анализ времени проверки MAC
- Защита: сравнение в постоянное время

---

### 4.6 MAC vs Encrypt-then-MAC vs MAC-then-Encrypt

**Три подхода:**

```
1. Encrypt-and-MAC (SSH):
   C = E(K₁, P)
   T = MAC(K₂, P)
   Отправить: (C, T)

2. MAC-then-Encrypt (TLS ≤ 1.2):
   T = MAC(K₂, P)
   C = E(K₁, P || T)
   Отправить: C

3. Encrypt-then-MAC (IPsec, TLS 1.3):
   C = E(K₁, P)
   T = MAC(K₂, C)
   Отправить: (C, T)
```

**Рекомендация:** **Encrypt-then-MAC** или **AEAD (GCM, ChaCha20-Poly1305)**

---

### 4.7 Сравнение реализаций MAC

| MAC | Основа | Скорость | Размер тега | Применение |
|-----|--------|----------|-------------|------------|
| HMAC-SHA256 | SHA-256 | Средняя | 256 бит | Универсальный |
| HMAC-SHA512 | SHA-512 | Средняя | 512 бит | Высокая безопасность |
| CMAC-AES | AES | Высокая | 128 бит | Когда есть AES |
| GMAC | AES-GCM | Очень высокая | 128 бит | С GCM |
| Poly1305 | Полиномы | Очень высокая | 128 бит | С ChaCha20 |

---

### 4.8 Практические рекомендации

1. **Используйте AEAD режимы** (GCM, ChaCha20-Poly1305) вместо отдельных MAC
2. **Длина тега:** минимум 128 бит для серьёзных применений
3. **Ключ MAC:** отдельный от ключа шифрования
4. **Сравнение тегов:** в постоянное время (защита от timing attacks)
5. **Защита от replay:** добавляйте nonce/sequence numbers

## Краткое резюме

| Тема | Ключевые моменты |
|------|------------------|
| **3DES** | EDE схема, 112-168 бит ключ, обратная совместимость с DES, deprecated |
| **ECB** | Не использовать! Утечка паттернов |
| **CBC** | Требует IV, нужен MAC, уязвим к padding oracle |
| **CTR** | Параллелизм, произвольный доступ, нужен MAC |
| **GCM** | CTR + GHASH, AEAD, рекомендуется |
| **Rabbit** | 128-бит ключ, 513-бит состояние, очень быстрый |
| **MAC** | Целостность + аутентификация, HMAC наиболее распространён |
| **AEAD** | Шифрование + аутентификация вместе (GCM, ChaCha20-Poly1305) |
